# 共有の Bot グループ

グループは、名前の付いた、順番のある Bot の一覧です。`/bot` は 1 つの対象としてグループを指定できます。
`#miners` はすべてのメンバー、`#miners[2]` は 1 体です。グループには持ち主がいて、共有か非公開のどちらかです
([PERMISSIONS.md](../PERMISSIONS.md#ownership))。

規模: メンバーを探すときは、runtime の軽い `profiles` 一覧 (名前、ID、状態だけ) を読みます。制御の
プロトコルは、要求と応答をそれぞれ 1 MiB までに制限します。これで、数百体のメンバーへのグループの一括入力と、
数千体の Bot のプロファイル一覧が収まります。以前の上限は 64 KiB で、Bot のプロファイルが 100 から 200 体ほどになると、
グループのすべての操作が失敗していました。

<a id="try-the-command-flow"></a>
## コマンドの流れを試す

権限のあるコントローラーかサーバーコンソールから実行します (コンソールでは先頭のスラッシュを省きます):

```text
/bot Alice spawn
/bot Bob spawn
/botgroup create #miners
/botgroup add #miners Alice
/botgroup add #miners Bob
/botgroup list
/botgroup list #miners
/bot #miners stop
/bot #miners[1] look 0 90
/bot #miners destroy count 64
/bot #miners destroy stop
/botgroup result #miners
/botgroup result #miners 2
```

ゲームプレイの操作の前に、Bot がオンラインになるのを待ち、いつもどおり道具と対象を用意してください。返事は
操作を受け付けたことを確認するもので、ワールドでの結果が成功したことを示すものではありません。
`destroy count 64` は、既存の完了の上限を Bot ごとに個別に設定します。グループ全体で共有する合計を分け合うのでは
ありません。

`/botgroup list` は共有グループを一覧表示します。`#miners` を付けると、そのグループのメンバーを表示します。
`/botgroup help` は管理の書き方を表示します。グループの指定には、作成のときも含めて、常に `#` を使います。
以前の `members` サブコマンドは `list` にまとめられました。`members` と、`#` のないグループの引数は、もう受け付け
ません。保存されている名前と UUID は変わらないので、既存のグループに移行の作業はいりません。メンバーを外すには
`/botgroup remove #miners Alice` を使います。見つからないプロファイルの項目を外すには
`/botgroup remove #miners #miners[1]` を使います。
`/botgroup delete #miners` はグループの登録を削除し、Bot のプロファイルはそのまま残します。
OS の CLI を使うときは、コマンド全体を引用符で囲みます。例: `endbot console "bot #miners stop"`。

<a id="menus-and-operation-results"></a>
## メニューと操作の結果

`/bot` または `/bot menu` は、個々の Bot と、直接操作できる `#group (count)` の対象を一覧表示します。グループを
選ぶと `/bot #miners menu` が開きます。これは 1 体の Bot と同じ操作画面の組み立てと分類を使います。すべて止める
(stop)、移動、向きを変える (look)、テレポート、ゲームプレイ、インベントリ、Bot の設定です。呼び出した人の操作履歴も
あります。グループの操作は、オンラインとオフラインが混じったグループや空のグループでも使えます。実行すると、
操作ごとの失敗がいつもどおり報告されます。
グループの対象は、`#` の接頭辞とメンバー数の付いた普通のボタンです。大きすぎるグループの見出しはありません。
**グループ管理...** は、選んだグループの `/botgroup menu #group` 画面を開きます。管理画面から入ったときは、
既存の **グループの管理へ戻る** ボタンが同じ役目をするので、リンクは重複して出ません。

`/botgroup` だけ (または `/botgroup menu`) で、グループの一覧と作成の画面が開きます。`/botgroup menu #miners` は
管理画面を開きます。接続状態の付いた順番どおりのメンバー、メンバーの追加と外す操作、確認つきのグループの削除が
あります。**グループを一括操作...** は同じ共通の操作画面を開き、**グループの管理へ戻る** でこの管理画面に戻ります。
メンバーは 10 体ずつページに分かれます (`/botgroup menu #miners 2`)。1 体を選ぶとその Bot の普通のメニューが開き、
入れ子の移動を通して管理画面への戻り道を保ちます。直接開いた `/bot #group menu` は、Bot と対象の一覧に戻ります。

テレポート、resume / spawn (座標の指定も含む)、reconnect / despawn、チャンク半径、状態、ブロックの操作は、
共通の操作メニューから使えます。グループ全体の名前の変更と forget は、コマンドでは引き続き拒否され、グループの
メニューにも出ません。個々の Bot のプロファイルの操作にはあります。入力フォームは既存のコマンドの意味を使います。
テレポート、spawn、ブロックの操作の `~` 座標はコントローラーからの相対で、look at と採掘の座標は各 Bot からの相対です。
グループの設定では、1 体のメンバーの値をグループ全体の今の値として表示せず、フォームの既定値を使います。
隊列や散開の機能はありません。時間と回数の上限は Bot ごとに適用されます。

フォームから送る変更は、どれも同じ `/bot` または `/botgroup` のコマンドと権限の経路を通り、実際のルートと引数を
チャットに表示します。送信のときに、グループと Bot の UUID、メンバーの順番を確かめます。メンバーを変えたり、
グループを削除して作り直したりしたら、古いフォームは開き直す必要があります。メンバーの 1 体用のフォームも、
画面を移動する間 UUID のチェックを保ちます。そのため、古い名前を使った別の Bot を間違って操作することはありません。
管理のフォームを閉じたりキャンセルしたりしても、操作は実行されません。グループを削除しても、その Bot の登録は
残ります。

変更を伴うグループ全体のコマンドの受付の返事は、失敗の数にかかわらず最大 **2 行** です。受付、失敗、未実行の数と、
必要なら分類ごとにまとめた失敗の理由です。表示する分類は最大 3 つで、それを超えた分は「ほか」として数えます。
これらは受け付けたことを確認するもので、ワールドでの結果が成功したことを示すものではありません。一括の入力を
送った後に応答がなかったものは **受付不明** として数えます。何も言わずに未実行と表すことはなく、自動で再試行する
こともありません。
番号付きの対象では、1 体のメンバーへの普通の返事に、グループの番号と Bot の名前が残ります。

変更を伴うグループの操作は、同じ上限のある英語の要約を、コントローラーの名前も含めてサーバーのログに書きます。
プレイヤーへの返事は、そのプレイヤーの言語になります。メニュー、結果の確認、読み取り専用の問い合わせは、監査の
記録を追加しません。
上限は、コマンドへのすぐの受付の返事に適用されます。BDS の参加と退出のイベントや、既存の非同期の採掘の通知は、
別のイベントです。メンバーごとの詳細は、通常の受付の返事や監査ログに書き出されません。

読み取り専用の `/bot #miners status`、`/bot #miners hotbar`、`/bot #miners radius` は、すべてのメンバーの実際の
問い合わせ結果をすぐに表示します。`#group[index]`、Bot の名前、メンバーごとのエラーも含みます。番号付きの
問い合わせも同じ形式です。明示的な問い合わせには、10 行のページや 2 行の要約の上限がありません。問い合わせの
データは、保存される操作の詳細の長さに切り詰められません。監査の記録は追加されず、操作履歴を作ったり、置き換えたり、
進めたりもしません。たとえば `jump` の後に `status` を確かめても、その `jump` の結果は履歴 1 のままです。ホットバーの
スロットや半径の値 (`default` も含む) を指定するのは変更なので、上限のある受付の返事、履歴、監査の動きのままです。

`/botgroup result #miners [history]` は、保存された 1 つの操作の **すべてのメンバーの行** を表示します。対象と操作、
数、メンバーごとの結果と理由を含みます。番号を省く (または `1` を使う) と最新の操作です。`2` は 1 つ前の操作、
`3` はその前です。これは保存された要求の結果を確かめるもので、再実行や新しい状態の問い合わせではありません。
メニューも同じスナップショットを使い (`/botgroup menu #miners result [history]`)、前後の結果へのボタンがあります。
スナップショットは、グループを対象にした変更を伴う `/bot` の要求を記録します。問い合わせ、管理の確認、メニューの
移動では置き換わりません。
コントローラーとグループの組ごとに結果を 20 件まで残します。全体の上限は 128 件で、古いものから消えます。これらは
メモリ上にあり、再起動で消えます。コンソールと CLI は、コンソールの結果の枠を共有します。ほかのコントローラーの
操作が、あなたの結果を上書きすることはありません。
詳細は、要求した時点の言語のままです。メンバーを編集したり Bot の名前を変えたりしても、過去の結果の行は
変わりません。グループを削除して作り直しても、前のグループの結果は見えません。メニューの移動では結果の UUID を
固定するので、新しい操作で前後の行き先がずれることはありません。消えた結果を見るには、履歴を開き直す必要が
あります。

メンバーを追加するフォームと外すフォームは、対象のグループを示し、送信ボタンのラベルは **追加** と **外す** です。
グループの削除には、タイトル、説明、確認ボタンにグループの名前が入ったアクションフォームを使います。登録された
Bot は残ります。
このアクションフォームの配置は、ユーザーのクライアントでタイトルと内容が空に見えていたメッセージフォームの配置に
代わるものです。

<a id="how-groups-behave"></a>
## グループの動き

- 共有グループは、既存のコントローラー権限を使います。`/botgroup` と `/bot` は、同じ認可、権限の版のチェック、
  順番どおりの worker を通ります。順に実行する操作は、要求の前とメンバーの間で権限を確かめ直します。一括の入力は、
  準備の間ずっと、そして一括を送る直前に確かめ直します。
- メンバーは、変わらない Bot の UUID として `state/groups.json` (endbotd より前は、プラグインのデータディレクトリの
  `groups.json`) に保存され、アトミックに書き込まれます。
  名前を変えてもメンバーのままです。古い名前を持つ別の Bot が、自動でメンバーになることはありません。
- メンバーの一覧は、一括の操作を始めた時点で固定されます。メンバーがオフラインになっても、メンバーの順番は
  変わりません。見つからないプロファイルは項目を保ち、個別の失敗になります。`spawn` がその項目の代わりを作る
  ことはありません。
- グループ全体の `move`、`look` (`look at` も含む)、`jump`/`attack`/`use`、`sprint`/`sneak`、`stop`、`hotbar`、
  `drop` は、プロファイルのスナップショットを 1 回取り、UUID で固定した一括入力を 1 回送ります。runtime はこれらを
  1 回の同期した処理で適用し、Bot ごとのエラーと返事はメンバーの順番に並びます。`look at` の Bot ごとの座標は、
  処理の前に解決します。メンバーと報告の順番のために、開始をずらす必要はありません。それでも、ネットワークと入力の
  tick は Bot ごとに独立しているので、同じ BDS の tick になることや、動きが同時に見えることは保証されません。
- 接続の管理の操作、テレポート、採掘、そのほかの操作は、既存の順に実行する経路のままです。
- 1 体のメンバーが失敗しても、残りの Bot は飛ばされません。一括の準備中に権限の取り消しやプラグインの停止が
  あると、一括入力の全体が送られません。順に実行している間なら、残りの要求が取り消されます。送った即時入力の
  一括は、メンバーごとの権限の呼び出しなしに、runtime の 1 回の処理で最後まで実行されます。受け付けた後に権限を
  取り消しても、その入力は元に戻りません。連続採掘の権限の取り消しとリースの既存の動きは、引き続き適用されます。
- runtime への要求は期待する UUID を持ち、古い Bot の名前や再利用された Bot の名前を、操作を適用する前に拒否します。
  これはプラグインの UUID による検索を補うもので、Microsoft/Xbox やローカル Bot のログインの経路は変えません。
- グループ全体の名前の変更と forget は拒否されます。これらの操作には、1 体のメンバーか Bot の名前を使います。
  グループ全体の `/bot ... menu` は共通の操作画面を開き、番号付きの `menu` は既存の 1 体の Bot の画面を開きます。
  `/botgroup menu #group` は、操作への入れ子のリンクを持つ、別の管理画面を開きます。
- `/botgroup` は、`list`、`help`、`create`、`delete`、`add`、`remove`、`menu`、`result` について、別々の標準の
  ヒントを出します。`list` には任意のグループの範囲、ほかにはグループ、Bot、メンバーの引数のヒントがあります。
  `/bot` と同じく、汎用の解析しやすさと型付きの列挙を組み合わせる方法を使います。固定している標準のパーサーのために、
  汎用の分岐 (番号でメンバーを外すものも含む) が残ります。この基準では、グループや Bot の名前を動的に候補に出す
  ことはできません。標準のクライアントでの絞り込みは、まだ弱いことがあります。

<a id="rules-and-limits"></a>
## ルールと上限

- グループ名は大文字と小文字を区別しません。ASCII の英字かアンダースコアで始まり、ASCII の英字、数字、
  アンダースコアを最大 16 文字使います。表示には保存したときの書き方を使います。
- メンバーを外すと、後ろの番号が詰まります。追加し直すと末尾に付きます。オフラインや登録を削除した項目は、自動では
  詰まりません。明示的に並べ替える方法はありません。
- グループの名前は変えられません。
- 一括のテレポートは、既存の 1 体の Bot のテレポートをそれぞれ独立に適用します。自動の隊列、ぶつからない散開、
  動いているプレイヤーに対する固定した共通の行き先はありません。置く場所が大事なときは、番号付きのコマンドを
  使ってください。
- グループのフォーム、結果の要約、普通のアクションの返事は、コントローラーの言語になります。グループの管理の
  診断メッセージには、英語のままのものがあります。

<a id="known-limits"></a>
## 既知の制限

- `/botgroup` は、役に立つ候補の代わりに、汎用の `<action: string>` / `<arguments: message>` の使い方を表示します。
  コマンドは受け付けられます。`/bot` と同じく、補完は弱いです
  ([#283](https://github.com/amatouhake/endbot/issues/283))。
- Bedrock の `string` 型の対象の引数は、先頭の `#` を拒否します。そのため、コマンドは対象と残りをまとめて 1 つの
  message として受け取り、自分で解析します。
- グループ全体への入力は、runtime の 1 回の処理ですべてのメンバーに届きます。ただし、Bot ごとにネットワークと入力の
  tick があるので、メンバーが同じ BDS の tick で動くことは保証されません。
- オフラインのメンバーに操作が効くかどうかは、操作によります。`stop` は受け付けられ、`jump` のようなオンライン専用の
  入力は、そのメンバーだけが失敗します。

サーバーとクライアントで確かめたことは、[検証状況](../COMPATIBILITY.md#bot-operations)
([記録](https://github.com/amatouhake/endbot/blob/cad9d962b49dedabb60d6dd37641c67d2e31df84/docs/GROUPS.md#verification))
にあります。グループのプローブの実行方法は、[WINDOWS_DEV.md](../WINDOWS_DEV.md#live-scripting-and-group-probes) を
見てください。
