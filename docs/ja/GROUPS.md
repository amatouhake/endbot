# 共有の Bot グループ

グループは、名前の付いた、順番のある Bot の一覧です。`/bot` で 1 つの対象として指定できます。`#miners` はすべてのメンバー、`#miners[2]` は 2 番目のメンバーだけを指します。

グループには持ち主がいて、共有か非公開のどちらかです ([PERMISSIONS.md](../PERMISSIONS.md#ownership))。このページのコマンドはすべて、権限のあるコントローラーかサーバーコンソールから使えます (コンソールでは先頭のスラッシュを省きます)。

<a id="try-it"></a>
## 試してみる

```text
/bot Alice spawn
/bot Bob spawn
/botgroup create #miners
/botgroup add #miners Alice
/botgroup add #miners Bob
/botgroup list #miners
/bot #miners stop
/bot #miners[1] look 0 90
/bot #miners destroy count 64
/bot #miners destroy stop
/botgroup result #miners
```

ゲームプレイの操作の前に、Bot がオンラインになるのを待ち、いつもどおり道具と対象を用意してください。返事は操作を受け付けたことを確認するもので、ワールドで成功したことを示すものではありません。

<a id="menus"></a>
## メニュー

`/bot` (または `/bot menu`) は、あなたの Bot とグループを一覧にします。グループは `#group (count)` と表示されます。グループを押すと、その操作画面が開きます。

| コマンド | 画面 |
| --- | --- |
| `/bot #miners menu` | グループ全体の操作 |
| `/bot #miners[1] menu` | そのメンバー 1 体のふつうのメニュー |
| `/botgroup` または `/botgroup menu` | グループの一覧とグループの作成 |
| `/botgroup menu #miners [page]` | 1 つのグループの管理 |
| `/botgroup menu #miners result [history]` | 保存された結果。一つ前 / 新しい結果のボタン付き |

<a id="operation-screen"></a>
### 操作画面

グループの操作画面には、1 体の Bot と同じ分類があります。止める、移動、向きを変える、テレポート、ゲームプレイ、インベントリ、Bot の設定、それにあなたの操作の履歴です。テレポート、resume と spawn (座標の指定も)、reconnect と despawn、チャンクの範囲、状態、ブロックの操作もすべてあります。

- オンラインとオフラインのメンバーが混じったグループでも、空のグループでも使えます。失敗はいつもどおり返事に出ます。
- 名前の変更と forget はありません。メンバー自身のメニューを使ってください。
- 設定のフォームは、どれか 1 体のメンバーの現在の値ではなく、既定値から始まります。
- **グループ管理...** は、このグループの管理画面を開きます。

<a id="management-screen"></a>
### 管理画面

`/botgroup menu #miners` は、メンバーを順番に、接続状態と一緒に表示します。ここから、メンバーを加えたり外したり、グループを削除したり (確認つき) できます。

- メンバーは 1 ページに 10 体ずつ表示します。`/botgroup menu #miners 2` は 2 ページ目です。
- メンバーを押すと、その Bot のふつうのメニューが開きます。奥へ進んでも、管理画面へ戻る道は保たれます。
- **グループを一括操作...** は操作画面を開きます。その画面の **グループの管理へ戻る** ボタンで、ここに戻ります。
- `/bot #group menu` で直接開いた操作画面では、代わりに Bot とグループの一覧に戻ります。
- メンバーを加えるフォームと外すフォームにはグループ名が表示され、**追加** と **外す** で送信します。削除のフォームは、タイトル、本文、ボタンにグループ名を表示します。Bot の登録は残ります。

<a id="how-forms-behave"></a>
### フォームのふるまい

- フォームを送信すると、同じ権限で同じ `/bot` か `/botgroup` のコマンドが実行され、そのコマンドがチャットに表示されます。
- メンバーが変わったり、グループが削除されて作り直されたりすると、古いフォームは拒否されます。開き直してください。
- メンバーのフォームは、同じ Bot を操作し続けます。古い名前を引き継いだ新しい Bot は、そのフォームでは操作されません。
- フォームを閉じたりキャンセルしたりしても、何も起きません。

<a id="managing-groups"></a>
## グループを管理する

`/botgroup` でグループを作成、編集します。グループ名は、作成するときも含めて、常に `#` で始めます。

```text
/botgroup create #group
/botgroup add #group <Bot>
/botgroup remove #group <Bot>|#group[index]
/botgroup delete #group
/botgroup list [#group]
/botgroup result #group [history]
/botgroup menu [#group [page]]
/botgroup help
```

| アクション | すること |
| --- | --- |
| `create` | 空のグループを作ります。 |
| `add` | 一覧の末尾に Bot を加えます。 |
| `remove` | Bot の名前でメンバーを外します。もう存在しないプロファイルの項目は、番号 (`#miners[1]`) で外します。後ろのメンバーの番号は 1 つずつ繰り上がります。 |
| `delete` | グループを削除します。Bot の登録は残ります。 |
| `list` | グループを付けないと共有グループの一覧、付けるとそのメンバーを表示します。 |
| `result` | 保存された操作について、各メンバーの結果を表示します ([後述](#operation-results))。 |
| `menu` | グループの画面を開きます ([後述](#menus))。`/botgroup` だけでも同じです。 |
| `help` | 管理の書き方を表示します。 |

グループの公開範囲と持ち主の設定 (`/botgroup visibility`、`/botgroup owner`) は [COMMANDS.md](COMMANDS.md#shared-group-menus-and-results) で説明しています。

例:

```text
/botgroup remove #miners Alice
/botgroup remove #miners #miners[1]
```

注意:

- `#` のないグループ名は受け付けません。サブコマンド `members` も受け付けません。代わりに `list #group` を使ってください。
- OS のコマンドラインからは、コマンド全体を引用符で囲みます: `endbot console "bot #miners stop"`。

<a id="operating-a-group"></a>
## グループを操作する

ふつうの `/bot` コマンドの対象としてグループを使います。

```text
/bot #group <operation> [arguments]
/bot #group[index] <operation> [arguments]
```

| 対象 | 届く相手 |
| --- | --- |
| `#miners` | すべてのメンバー。一覧の順です |
| `#miners[2]` | 2 番目のメンバーだけ。返事は 1 体の Bot のときと同じ形で、番号と Bot の名前が付きます |

例:

```text
/bot #miners move forward for 40
/bot #miners[1] tp me
```

注意:

- 回数と時間は Bot ごとに別々に適用されます。`destroy count 64` では、メンバーそれぞれが 64 ブロックを掘ります。64 をグループで分け合うのではありません。
- 失敗したメンバーがいても、ほかのメンバーは止まりません。
- グループ全体への `rename` と `forget` は受け付けません。1 体のメンバー (`#miners[1]`) か Bot の名前を使ってください。
- ほかの人が持ち主で、非公開にしているメンバーは、1 体ずつ拒否されます。グループの残りはそのまま実行されます ([PERMISSIONS.md](../PERMISSIONS.md))。
- メニューからの操作は 1 体の Bot と同じで、`~` の決まりも同じです。テレポート、spawn、ブロックの操作の座標はあなたからの相対、look at と採掘の座標は各 Bot からの相対です。

<a id="which-operations-reach-members-together"></a>
### メンバーに一斉に届く操作

| 操作 | 実行のしかた |
| --- | --- |
| `move`、`look` (`look at` を含む)、`jump`、`attack`、`use`、`sprint`、`sneak`、`stop`、`hotbar`、`drop` | すべてのメンバーに一斉に送ります。ただし、Bot ごとにネットワークと入力のタイミングが別なので、メンバーが同じゲーム tick に動くとは限りません。 |
| 接続の操作 (`spawn`、`despawn`、`reconnect` など)、テレポート、採掘、その他 | 一覧の順に、1 体ずつ順番に実行します。 |

<a id="offline-and-missing-members"></a>
### オフラインのメンバーと見つからないメンバー

- オフラインのメンバーがどうなるかは、操作によります。`stop` は受け付けられます。`jump` のようにオンラインのときだけ使える入力は、そのメンバーだけが失敗します。
- プロファイルが削除されたメンバーは、一覧での位置を保ったまま、それだけが失敗します。`spawn` でその Bot が新しく作られることはありません。`/botgroup remove #miners #miners[index]` で項目を外してください。
- メンバーの一覧は、操作を始めた時点で決まります。

<a id="losing-permission-while-it-runs"></a>
### 実行中に権限を失ったとき

- 一斉に送る操作を送る前に、権限が取り消されたりプラグインが停止したりすると、何も送りません。
- 1 体ずつ順番に実行する操作の途中なら、残りのメンバーは実行しません。
- すでに受け付けられた一斉の操作は、取り消されません。連続採掘は、1 体の Bot のときと同じように止まります。

<a id="results"></a>
## 結果

グループの操作がすぐに返す返事、クエリで分かること、操作ごとに保存される結果です。

<a id="replies"></a>
### 返事

グループ全体への、何かを変えるコマンドの返事は、失敗したメンバーが何体いても **2 行まで** です。

| 部分 | 意味 |
| --- | --- |
| 受付 / 失敗 / 未実行 | それぞれの状態のメンバーの数 |
| 受付不明 | 要求は送りましたが、応答が返ってきませんでした。実行されたかどうかはわからず、再試行もしません。 |
| 失敗の理由 | 分類ごとにまとめ、最大 3 つまで表示します。残りは「ほか」として数だけを示します |

この返事の意味は「受け付けた」で、「ワールドで完了した」ではありません。各メンバーの結果は [`/botgroup result`](#operation-results) で見てください。

注意:

- これらの変更は、あなたの名前を付けた英語の短い要約として、サーバーのログにも書かれます。メニュー、問い合わせ、`result` はログに書かれません。
- 参加と退出のメッセージや採掘の通知は別のメッセージで、この 2 行には含まれません。

<a id="queries"></a>
### 問い合わせ

問い合わせは、すべてのメンバーの答えをまとめて表示します。

```text
/bot #group status
/bot #group hotbar
/bot #group radius
```

各行は `#group[index]` と Bot の名前で始まります。失敗したメンバーは、そのエラーを 1 行で表示します。番号付きの対象 (`#miners[2] status`) も同じ形です。

注意:

- 問い合わせは 10 行や 2 行に切り詰めません。
- 問い合わせはログに書かれず、[`result`](#operation-results) の履歴も変えません。`jump` の後に `status` で確かめても、結果 1 は `jump` のままです。
- 値を指定する (`hotbar 3`、`radius 8`、`radius default`) と、問い合わせではなく変更になります。2 行の返事になり、ログに書かれ、結果として保存されます。

<a id="operation-results"></a>
### 操作の結果

`/botgroup result` は、保存された 1 つの操作について、各メンバーの結果を表示します。

```text
/botgroup result #group [history]
```

| `history` | 表示する操作 |
| --- | --- |
| 省略または `1` | 最新 |
| `2` | 1 つ前 |
| `3` | さらにその前 (以下同様) |

表示には、対象、操作、数、各メンバーの結果と理由が入ります。何も再実行せず、Bot に問い合わせ直すこともありません。操作を送ったときに起きたことを表示します。

例:

```text
/botgroup result #miners 2
```

注意:

- 保存するのは、グループ全体への何かを変えたコマンドだけです。問い合わせ、管理の確認、メニューの移動は保存しません。
- コントローラーごと、グループごとに最大 20 件、サーバー全体で最大 128 件の結果を保持し、古いものから消します。結果はメモリにだけあり、サーバーの再起動で消えます。
- あなたの結果はあなただけのものです。ほかのコントローラーの操作で置き換わることはありません。コンソールと OS のコマンドラインは 1 つの枠を共有します。
- 結果は、作られたときの言語のままです。メンバーを変えたり Bot の名前を変えたりしても、保存済みの行は変わりません。削除して作り直したグループには、前のグループの結果は表示されません。
- メニューでは、新しい操作が来ても、一つ前 / 新しい結果のボタンは見ていた結果の位置にとどまります。その間に結果が消えていたら、履歴を開き直してください。

<a id="limits"></a>
## 制限

グループが従うルールと、まだうまく動かないことです。

<a id="rules-and-limits"></a>
### 決まりと制限

- **名前:** 大文字と小文字を区別しません。ASCII の英字、数字、`_` で 16 文字までで、英字か `_` で始めます。表示には、入力したときの綴りを使います。
- **順番:** メンバーを外すと、後ろのメンバーの番号が 1 つずつ繰り上がります。もう一度加えると末尾に付きます。オフラインのメンバーや forget したメンバーも位置を保ちます。並べ替えのコマンドはありません。
- **名前の変更:** グループの名前は変えられません。名前を変えた Bot はメンバーのままです。古い名前の新しい Bot はメンバーではありません。
- **テレポート:** 各メンバーは、1 体の Bot のときとまったく同じように、それぞれテレポートします。隊形も、ぶつからないように散らす処理も、あなたが動いているときの共通の固定の行き先もありません。配置が大事なときは、番号付きのコマンドを使ってください。
- **言語:** フォーム、結果、ふつうの返事は、あなたのゲームの言語を使います。管理のメッセージの一部は英語のままです。

<a id="known-limits"></a>
### 既知の制限

- `/botgroup` は、役に立つ候補ではなく、汎用の `<action: string>` / `<arguments: message>` という書き方を表示します。コマンドは動きます。`/bot` と同じく、補完が弱いだけです ([#283](https://github.com/amatouhake/endbot/issues/283))。
- 一斉の操作のメンバーが同じゲーム tick に動くとは限りません ([前述](#which-operations-reach-members-together))。

実際のサーバーとクライアントで確認したこと: [検証の状況](../COMPATIBILITY.md#bot-operations)。グループのしくみ: [BOT_CONTROL.md](../BOT_CONTROL.md#groups)。
