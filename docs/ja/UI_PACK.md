<a id="optional-endbot-ui-resource-pack"></a>
# 任意の Endbot UI リソースパック

*Endbot UI* は、プレイヤーが自分のクライアントに入れる任意のリソースパックです。ゲーム内のメニューを大きくし、
スクリプトのエディターに複数行の欄を用意します。パックがなくても、1 つの欄でスクリプト全体を編集すること以外は
すべて使えます。パックに頼るサーバーの機能 `[scripting] ui-pack-editor` は、既定ではオフです。モバイルの
クライアントでの欄の動きと、パックを有効にした状態での新しい実績の解除は、確かめていません
([#277](https://github.com/amatouhake/endbot/issues/277))。

<a id="why"></a>
## なぜ必要か

クライアントの 2 つの制限のため、ゲーム内でのスクリプトの編集は大変です:

- サーバーのフォームは 225×200 UI 単位の固定のウィンドウで、ボタンの高さは 32 単位です。そのため、メニューを
  何度もスクロールすることになります。
- フォームのテキスト欄は短く、**改行が消えます**。そのため、複数行のソースは本と羽根ペンを通す必要があります。

どちらも、サーバーがフォームに入れられるものでは直せません。リソースパックなら、クライアント側でフォームの画面の
見た目を変えられます。このパックは、ゲーム内での当面のしのぎです。長い目で見た書き方は、引き続き
[ウェブエディター](../WEB_DEPLOY.md)です。構文の色分け、補完、差分を出せるのはウェブエディターだけです。

<a id="what-it-changes"></a>
## 変わること

`ui-pack/` は、バニラの要素 `server_form.main_screen_content` を 1 つだけ上書きします。これにより、サーバーの
フォームは、バニラの要素をもとに作った `endbot_*` の要素を使います:

| 変更 | 対象 | 方法 |
|---|---|---|
| 大きいウィンドウ: 画面の大きさから余白を引いた大きさで、最大 420×300 (バニラは 225×200) | すべてのサーバーのフォーム | `endbot_long_form`、`endbot_custom_form` |
| 小さめのボタン: 高さ 24 単位 (バニラは 32)、アイコンは 24 単位 | すべてのアクションフォーム | `endbot_dynamic_button` |
| 複数行の欄: 高さ 150 単位、スクロールでき、Enter で改行が入り、最大 32768 文字 | ラベルが Endbot の目印で始まる入力だけ | `endbot_input` → `endbot_multiline_input` |

**目印** は `§e§b§o§t§r` (`forms.MULTILINE_MARKER`) で、何も描かない書式コードです。プラグインは、
`TextInput(..., multiline=True)` のラベルの前にこれを付けます。パックのないクライアントは、ラベルをそのまま表示し、
いつもの 1 行の欄を出します。パックのあるクライアントは、各入力のラベルに目印があるかを確かめ
(`(#custom_text - '<marker>') = #custom_text`)、目印の付いた入力にだけ縦に長い欄を出します。

今、目印が付いている入力:

- **全体をまとめて編集 (UIパック)...**: スクリプト全体を 1 つの欄に入れます。サーバーが `[scripting] ui-pack-editor`
  を有効にしていると、行の編集画面に出ます。保存では、ほかのすべての保存と同じコンパイル、宣言、持ち主、版の
  チェックを通ります。改行が失われた応答は **拒否され、保存されません**。パックがないと、クライアントの欄はすべての
  行を 1 行につなげてしまいます。そのため、複数行のスクリプトは、戻ってきたときにも 2 行以上ある必要があります。
  変更のない応答は、版を保存せずにエディターに戻ります。
- **新しいスクリプト** (テンプレートの欄): `ui-pack-editor` があると、新しいスクリプトの画面で、テンプレートを同じ
  目印付きの欄として出します。そのため、スクリプトができる前に、全体をまとめて書けます。応答の改行が失われたときは、
  同じように拒否します。1 行のテンプレートは 1 行のままでも構いません。テンプレートは欄の上にラベルとしても
  読めるので、パックのないクライアントでも、何が保存されるかを見られます。**表示どおりに保存 (UI パックなし)** の
  切り替えは、欄を無視してテンプレートをそのまま保存します。そのため、パックのないプレイヤーも、スクリプトを作って
  から行を編集できます (クライアントの欄は空にできません)。
- **下に行を追加** (行の編集画面) と **新しい行** (先頭か末尾に追加)。パックがなければ今までどおり動きます。
  パックがあれば、貼り付けたまとまりの行がそのまま保たれます (プラグインはもともと応答を改行で分けます)。

パックを入れている間は、ほかのサーバーのフォームも含めて、**すべての** サーバーのフォームの見た目が変わります
(大きいウィンドウ、小さいボタン)。縦に長い欄が出るのは、Endbot の目印付きの入力だけです。

<a id="install"></a>
## インストール

パックはクライアント側だけのものです。プレイヤーの端末に **グローバルリソースパック** として追加します。サーバーの
パックの一覧は空のままです。`world_resource_packs.json` も `texturepacks-required` も使いません。
`server.properties` は何も変わりません。

1. GitHub のリリースから `endbot-ui-<pack version>.mcpack` をダウンロードします。リリースのワークフローが候補版と
   並べてビルドし、`SHA256SUMS` にも含まれます。配布はリリースのアセットだけで、外部のサイトはありません。
   バージョンはパック独自のもので、Endbot のバージョンとは別で、パックが変わったときだけ上がります。同じファイルを
   サーバーのリソースパックとして配る方法は、確かめていません。パックがサーバーのパックの一覧に入り、どのチェックも
   それを扱っていないからです。
2. Windows では、`.mcpack` ファイルを開きます。Minecraft が取り込みます。
3. **設定 → グローバルリソース** で *Endbot UI* を有効にします。
4. オペレーターが `[scripting]` の下に `ui-pack-editor = true` を設定し (プラグインの `config.toml`、管理された
   インスタンスでは `endbot.toml`)、再起動します。パックのないプレイヤーにもボタンは見えます。試すと、行のボタンか
   本を使うよう案内されます。新しいスクリプトの画面では、**表示どおりに保存** をオンにして、保存後に行を編集するよう
   案内されます。

モバイルのクライアントも、同じように `.mcpack` ファイルを取り込めます。コンソール機は任意のグローバルパックを
追加できないので、このパックは実質的に PC とモバイルのプレイヤー向けです。チェックアウトからファイルをビルドする
には、`python scripts/build_ui_pack.py` が `dist/ui-pack/endbot-ui-<version>.mcpack` を書き出します (再現可能です。
同じ入力からは同じバイト列ができます)。

<a id="name-icon-and-licence"></a>
## 名前、アイコン、ライセンス

パックの名前は **Endbot UI** です。manifest の説明には、何が変わるかと、任意であることが書いてあります。
`ui-pack/pack_icon.png` はクライアントが表示する 128x128 のアイコンです。元は `assets/icon/endbot-icon.svg` で、
README でも 512x512 で使っています。明るい版の `assets/icon/endbot-icon-light.svg` は明るい背景用で、まだ PNG の
書き出しはありません。どちらも 1024 のキャンバスに置いた角の丸い四角形です。`scripts/render_icons.ps1` は、
ヘッドレスの Chrome で暗い SVG をサイズごとに 1 回ラスタライズします。そのため PNG は SVG の書き出しで、手で編集する
ファイルではありません。

パックは zip の中に `LICENSE` (Apache-2.0) と短い `NOTICE` を含みます。プレイヤーはパックだけをダウンロードできる
からです。NOTICE は著作権者を示し、パックが実行時にバニラの要素の id を上書きすることと、Mojang のアセットを
含まないことを述べています。

取り除くには、グローバルリソースで無効にします。サーバー側の変更はいりません。パックを使うコントローラーが
いないときは、`ui-pack-editor` をオフのままにしてください。

<a id="achievement-safety"></a>
## 実績への影響

[実績のゲート](../ACHIEVEMENTS.md)は、パックの一覧が空で、グローバルパックもない状態で観測しました。このパックは、
サーバーにもワールドにも触れません。リソースだけのパックで、ビヘイビアーパック、スクリプト、実験的機能、Beta API は
ありません。リソースパックが実績を無効にするとは知られていません。それでも、**パックを有効にした状態でのワールドの
実績の解除は、それ自体が手動のゲートです** (AGENTS.md、チェック 10)。そのゲートは通っていません
([#277](https://github.com/amatouhake/endbot/issues/277))。解除を観測するまでは、パックが実績に対して安全だとは
言いません。

<a id="how-it-works"></a>
## しくみ

[bedrock-samples](https://github.com/Mojang/bedrock-samples) のバニラの UI (`ui/server_form.json`、
`ui/ui_common.json`、`ui/ui_template_buttons.json`、`ui/settings_sections/settings_common.json`) から読み取った
内容です。1.26.50.4 と `v1.26.60.5` で同じです:

- `server_form.custom_input` は **`$max_text_edit_length: 100`** を設定し、`common.text_edit_box` を継承します。
  これには `enabled_newline` がありません。そのため、バニラのフォームの入力では改行が消え、約 100 文字で止まります。
- `common.multiline_text_edit_box` と `common.scrollable_multiline_text_edit_box` は `enabled_newline: true` を
  設定し、`button.menu_ok` の割り当てを含みません。そのため、Enter で欄から抜けるのではなく、改行が入ります。本の
  エディターも同じしくみを使います。
- サーバーのフォームは 1 つのファクトリー (`main_screen_content`) で作られ、その `long_form` と `custom_form` の
  id がフォームの種類を決めます。パックは、その 2 つの id の行き先を変えます。
- パックの欄 `endbot_multiline_control` は `common.scrollable_multiline_text_edit_box` を継承し、`size` を 150、
  `max_length` を `$max_text_edit_length` (32768) から設定します。内容のバインディング (`custom_form` では
  `#custom_input_text`) は、バニラの `server_form.custom_input` から継承します。`#custom_input_enabled` を
  `custom_form` のコレクションから読み、`#focus_identifier` を `#custom_text` からバインドします。これはバニラが
  自分の複数行の入力に使う形です。コレクションには専用の id がないので、フォーカスの id はラベルです。1 つの
  フォームに目印付きの入力を 2 つ置くときは、ラベルを別々にする必要があります。
- サーバー側は何も変わりません。Endstone はモーダルフォームの応答を、文字列の内容を変えずにプラグインへ渡し、
  プラグインは `json.loads` でそれを読みます。BDS 自体による応答パケットの扱いは、ソースが公開されていません。

<a id="behaviour-on-the-client"></a>
## クライアントでの動き

Windows のクライアント 1.26.60.5 で、パックをグローバルリソースとして有効にし、既定の GUI の大きさ、1080p で見た
結果です
([記録](https://github.com/amatouhake/endbot/blob/cad9d962b49dedabb60d6dd37641c67d2e31df84/docs/UI_PACK.md#client-check-2026-11-03-jst-windows-126605)):

- `/bot` と `/botscript` は大きいウィンドウで開きます。ボタンは小さめで、切れるラベルはありません。
- 目印付きの入力には縦に長い欄が出ます。入力、バックスペース、Enter が使え、保存しても改行、日本語の文字、`§` の
  コード、タブ、行末の空白が保たれます。152 文字と 2603 文字の行、156 文字と 2508 文字の貼り付けが、すべて
  そのまま保たれました。
- **欄は、枠をクリックしたときだけフォーカスを受け取ります。** 欄の中のスクロールパネルがポインターの入力を
  受け取ってしまうので、テキストをクリックしてもカーソルが出ません。枠を 1 回クリックしてください。そうすれば、
  欄全体で編集でき、ホイールでスクロールし、カーソルに合わせて動きます。スクロールしない版はどこからでも
  フォーカスを受け取りますが、長いソースを表示できません。そのため、スクロールする版を使っています。
- **パックがないと、スクリプト全体の入力は使えません。** 欄にはスクリプトの最初の数行しか出ず、入力しても消しても
  何も起きず、約 100 文字で入力が止まります。そのため、この入力を使えるのはパックを入れたプレイヤーだけで、
  `ui-pack-editor` は、プレイヤーがパックを入れているオペレーターのためのスイッチです。
- **設定 → グローバルリソース** の一覧には、*Endbot UI* が 2 行の説明と抽象的な E のアイコンとともに表示されます。

確かめていないこと ([#277](https://github.com/amatouhake/endbot/issues/277)): モバイルのクライアントでの欄と、
パックを有効にした状態での新しい実績の解除です。

<a id="checking-the-pack-after-a-change"></a>
## 変更後のパックの確認

固定している組み合わせ (Endstone `0.11.15+endbot.1` / BDS `1.26.60.6`、protocol 2225) で、通常どおり認証した
Windows のクライアント (1.26.60.5) を使い、既定の GUI の大きさ、1080p で、パックをグローバルリソースとして
有効にして確かめます:

1. パックが、コンテンツログのエラーなしに取り込まれ、有効になる。*失敗* → エラーを書き留めます。バニラの要素の名前が
   変わったときは、たいていここに出ます。
2. `/bot` と `/botscript` のメニューが大きいウィンドウで開く。ボタンは小さめで、文字が切れない。ほかのフォーム
   (Bot のアクション、グループの画面) も引き続き動く。
3. **行を編集 → 下に行を追加** で縦に長い欄が出る。Enter を押すと改行が入り、保存で引き続き送信できる。
4. 3 行のまとまりを **下に行を追加** に貼り付けて保存する。3 行すべてが、説明どおりの字下げでその行の下に入る。
5. `ui-pack-editor = true` で: **全体をまとめて編集** に、スクリプト全体が改行つきで出る。2 行を変えて保存し、
   **以前の版** にちょうどその変更の新しい版が 1 つできたことを確かめる。
6. 100 文字より長いスクリプトと、2000 文字より長いスクリプトを貼り付ける。全部保たれるか、切れるか、切れるならどこで
   切れるか。パックなしで、100 文字より長い行を行の編集画面で変えずに保存したとき、その行は保たれるか。両方の答えを
   記録します。そこで切れるなら、既存の行の編集画面の不具合です。
7. ソースの中の日本語の文字と `§` の文字が、欄を往復しても残る。
8. パックを無効にする: 複数行のスクリプトで **全体をまとめて編集** すると保存が拒否され (「改行が失われた」)、
   スクリプトは変わらない。
9. モバイルのクライアント (任意): 手順 3 と 5。
10. パックを有効にした状態での実績のゲート: [ACHIEVEMENTS.md](../ACHIEVEMENTS.md) のとおり。
11. **設定 → グローバルリソース** に *Endbot UI* が出る: 名前、切れていない 2 行の説明、抽象的な E のアイコン。
    一覧は説明を切り詰めるので、それより長い説明なら省略記号が出ます。

結果は [#277](https://github.com/amatouhake/endbot/issues/277) に記録します。クライアントがパックの入力の要素を
使わないために 3–5 が失敗したときは、ウィンドウとボタンの変更は残し、`ui-pack-editor` はオフのままにします。

パックは非公式の JSON UI の内部に頼っているので、クライアントの更新で変わることがあります。Mojang は画面を Ore UI へ
移しつつもあります。サーバーのフォームが移ると、パックは効かなくなり、フォームはバニラに戻ります。サーバー側で
壊れるものはありません。クライアントの更新の後は、そのバージョンの `bedrock-samples/resource_pack` に対して
`python scripts/build_ui_pack.py --check --vanilla <dir>` を実行します。パックを変えたときは、`ui-pack/manifest.json`
の `header.version` とモジュールのバージョンを上げ (クライアントはパックをバージョンでキャッシュします)、チェック
1–5 を繰り返します。名前、説明、アイコンを変えたときは、チェック 11 も繰り返します。それらが表示されるのは
リソースの一覧だけだからです。`tests/test_ui_pack.py` は、パックの目印がプラグインのものと同じであることも含めて、
検証のオフラインの部分を CI で実行します。
